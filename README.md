# notion-crawling

노션에서 웹에 게시한 페이지를 로그인 없이 가져와 마크다운과 JSON으로 저장하는 크롤러.

공식 API는 연동 권한과 호출 제한 때문에 수백 개 페이지를 처리하기 어렵다. 이 프로젝트는 게시된 페이지만 대상으로, 노션 웹 화면이 내부적으로 쓰는 `/api/v3` 엔드포인트를 호출해 본문을 수집한다.

> 비공식 내부 API를 사용한다. 노션 쪽 응답 형식이 바뀌면 동작하지 않을 수 있다.

## 요구 사항

- Node.js 18 이상 (내장 `fetch` 사용)
- pnpm

## 설치

```bash
pnpm install
```

## 사용법

```bash
pnpm crawl <노션 게시 URL> [--depth=2]
```

| 옵션 | 기본값 | 설명 |
| --- | --- | --- |
| `--depth=N` | `2` | 하위 페이지를 따라갈 깊이. `0`이면 입력한 페이지만 수집 |

게시 URL은 노션에서 **공유 → 웹에 게시**를 켠 뒤 복사한 주소다. 주소 끝의 32자리 문자열이 페이지 ID로 쓰인다.

```bash
pnpm crawl "https://<workspace>.notion.site/<제목>-<32자리 ID>"
```

## 테스트

아래 페이지는 이 크롤러를 검증하려고 만든 테스트용 페이지다. 제목, 목록, 표, 코드, 토글, 콜아웃, 컬럼, 이미지, 파일, 하위 페이지, 인라인 데이터베이스, 200개 문단의 긴 본문이 들어 있다.

https://skinny-poinsettia-af1.notion.site/4083185c21be80278a0de97f93ec050b

```bash
pnpm crawl "https://skinny-poinsettia-af1.notion.site/4083185c21be80278a0de97f93ec050b"
```

실행하면 페이지별로 다음과 같이 출력된다.

```
✔ 노션 크롤링 테스트용 페이지 내용  blocks=327  md=15707자
  타입: {"header":2,"text":21, ...}
  DB 4083185c-...: 21/21행
  이미지 200 캡션
  이미지 200 (캡션 없음)
✔ 하위페이지 A  blocks=4  md=81자
...
```

확인할 점은 다음과 같다.

- `DB` 줄의 `받은 행/전체 행`이 같은지 (다르면 일부만 수집된 것)
- `이미지` 줄의 숫자가 `200`인지 (`-1`이면 접근 실패)
- 마크다운 마지막 문단까지 들어 있는지

## 출력 구조

`out/` 아래에 페이지마다 폴더가 하나씩 생기고, 하위 페이지는 부모 폴더 안에 들어간다. 폴더 이름은 `제목-ID 뒤 8자리`다.

```
out/
└─ 노션 크롤링 테스트용 페이지 내용-93ec050b/
   ├─ page.md
   ├─ page.json
   ├─ 하위페이지 A-36c205d8/
   │  ├─ page.md
   │  ├─ page.json
   │  └─ 하위 페이지 안에 하위 페이지-0f253041/
   └─ 하위 페이지 B-d69ddeb4/
```

- `page.md`: 본문 마크다운. 수집한 하위 페이지로 가는 링크는 상대 경로로 바뀐다. 깊이 제한으로 수집하지 않은 하위 페이지는 `page:<ID>`로 남는다.
- `page.json`: 블록 원본, 타입별 개수, 이미지 접근 결과, 데이터베이스 수집 현황, 하위 페이지 목록, 수집 시각.

`out/`은 `.gitignore`에 포함되어 있다.

## 지원하는 블록

| 분류 | 블록 |
| --- | --- |
| 텍스트 | 제목 1~4, 문단, 인용, 콜아웃, 구분선, 수식 |
| 목록 | 글머리 기호, 번호, 체크박스, 토글 |
| 구조 | 표, 컬럼, 목차 |
| 코드 | 코드블록 (언어 유지) |
| 미디어 | 이미지, 파일, PDF, 북마크, 임베드, 동영상 |
| 페이지 | 하위 페이지, 인라인 데이터베이스 (전체 행) |

위에 없는 블록은 `<!-- 지원하지 않는 블록: 타입 -->` 주석으로 남기고 자식 블록은 계속 따라간다.

## 코드 구조

```
src/
├─ core/           프레임워크와 파일시스템에 의존하지 않는 수집 로직
│  ├─ index.ts        공개 API
│  ├─ crawl-page.ts   crawlPage(origin, pageId) -> CrawledPage
│  ├─ client.ts       내부 API 호출 (페이지네이션, 누락 블록 보충, DB, 파일 서명 URL)
│  ├─ markdown.ts     블록 -> 마크다운
│  ├─ types.ts        CrawledPage 등 결과 모델
│  └─ url.ts          URL에서 origin과 페이지 ID 추출
└─ cli/crawl.ts    로컬 실행기. 폴더 트리 저장과 로그 출력
```

`core/`는 외부 패키지 없이 `fetch`만 쓰므로 다른 프로젝트(예: NestJS 서비스)에 그대로 가져가 쓸 수 있다.

```ts
import { crawlPage, parsePublicUrl } from "./core";

const { origin, id } = parsePublicUrl(url);
const page = await crawlPage(origin, id, { onWarn: console.warn });

page.title;     // 페이지 제목
page.markdown;  // 본문 마크다운
page.subpages;  // 하위 페이지 목록 (따라갈지는 호출하는 쪽이 결정)
```

`crawlPage`는 한 페이지만 수집하고 파일을 쓰지 않는다. 하위 페이지 재귀, 저장, 재시도, 동시 요청 수 조절은 호출하는 쪽에서 처리한다.

## 알려진 한계

- 비공개 페이지나 게시되지 않은 페이지는 수집할 수 없다. 이 경우 오류로 알린다.
- 노션에 업로드한 이미지와 파일은 서명 URL이라 시간이 지나면 만료될 수 있다. 보관이 필요하면 수집 시점에 바로 내려받아야 한다.
- 노션에서 수정한 직후에는 게시본에 반영되기까지 시간이 걸려, 이전 내용이 수집될 수 있다.
- 데이터베이스는 첫 번째 보기 기준으로 행을 가져온다. 필터나 정렬이 걸린 보기에서의 동작은 검증하지 않았다.
